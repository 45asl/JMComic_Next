# 1.8.0 lite 方案（待用户确认后开工）

目标：**在保证基本功能的前提下，以最强硬的手段削除非必要功能**，面向极低性能设备。

## 一、形态：Gradle product flavor（强烈建议），不是 git 分支

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A. product flavor**（建议） | 同一套代码出 `full` / `lite` 两个变体，功能用**编译期常量**区分 | 代码里维护一套开关（但配 R8，关掉的分支会**连代码一起被删掉**，不只是不执行） |
| B. git 分支 | 开 `lite` 分支独立演进 | **两个代码库**：每个 bug 修两遍、功能会漂移、每次改动都要 cherry-pick |

选 A 的核心理由：**lite 不是"另一款应用"，而是同一款应用的裁剪**。分支会让两者越走越远，
最终 lite 拿不到任何新修复 —— 而极低性能设备上的用户恰恰最需要修复。

## 二、功能清单与取舍（初稿，待你增删）

### 保留（基本功能）

| 功能 | 为什么必须留 |
| --- | --- |
| 首页分区浏览 / 分类 / 搜索 | 没有这些就不是阅读器 |
| **阅读器**（翻页、预取、进度记忆） | 核心功能 |
| 收藏 / 观看历史 / 追更 | 用户数据，砍掉等于丢数据 |
| **下载** | 低性能设备往往网络也差，离线阅读更必要 |
| **标签屏蔽** | 用户自己设的过滤，砍掉等于破坏他的设置 |
| 登录 | 收藏/历史都要账号 |
| 设置里的必要项（阅读偏好、存储、关于） | — |

### 砍掉（非必要）

| 功能 | 砍掉的理由 | 连带影响 |
| --- | --- | --- |
| **玻璃 / 模糊 / 通透模式 / 全部主题风格** | 每帧模糊是这台设备最可能的卡顿源 | 固定为纯色表面；`GlassSurface` 退化为普通 Surface |
| **壁纸（Bing 拉取 + 常驻模糊）** | 一个网络功能 + 一张常驻模糊的大图 | 背景固定纯色 |
| **莫奈取色 / 动态取色** | 需要系统取色管线 | 固定主色 |
| **全部动画**（动效性格、共享元素、预测性返回、条目进出场） | 低端机上动画是最直观的"卡" | 交互仍有即时反馈，只是不做过渡 |
| **悬浮底栏** | 玻璃材质之上的附加复杂度 | 用普通底栏 |
| 评论 | 非阅读必需 | — |
| 作者 / 书库页 | 同上 | — |
| 签到 / 通知（含 12 小时闹钟）/ 随机按钮 | 附带网络与后台成本 | 设置里对应项一并隐藏 |
| 周刊 | 同上 | — |

### 需要你拍板的三处（我拿不准）

1. **标签屏蔽**要不要留？它会在后台逐条读详情取标签（有并发上限与缓存），
   对低性能+差网络是持续成本。但砍掉会**破坏用户已有的屏蔽设置**。
   我倾向**保留**（用户数据优先）。
2. **下载**要不要留？它是另一个大模块（存储、任务管理）。低性能设备通常也需要它，
   我倾向**保留**，但如果你觉得该砍，它是最能减重的一块。
3. **签到**砍不砍？它几乎不耗性能（一个请求 + 一张卡片），
   但对"极低性能设备"，任何非核心功能都是负担。我倾向**砍**。

## 三、机制设计

- 编译期常量（`BuildConfig.LITE` 或 flavor 维度）—— **不是运行时开关**，
  这样 R8 能把 `if (!LITE)` 包住的整段代码与资源删掉。
- 一个 `LiteFeatures` 门面集中所有判断，避免 `if (LITE)` 散落各处（散落的开关迟早漏一个）。
- 主题层：lite 下 `JmTheme.spec` 固定返回纯色方案，`GlassSurface` 直接画普通 Surface
  —— **不在调用点写 if**，否则要改几十处、且以后每加一个卡片都要记得写。

## 四、验收方式（可量化，先量后改）

实现前后各测一次，数字入 CHANGELOG：

| 指标 | 怎么测 |
| --- | --- |
| APK 体积（压缩/未压缩，按 dex/res/arsc 分类） | 本地解析 APK（已有脚本） |
| 冷启动 `TotalTime` | `am start -W`（主机 + 虚拟机各 3 次） |
| 内存占用（PSS） | `dumpsys meminfo` 取 Total PSS |
| 帧率（滚动首页时的 jank 比例） | `dumpsys gfxinfo` 的 janky frames 统计 |

**最后一项是关键**：前几版我"能测启动、测不了流畅度"，而 `gfxinfo` 正好给出**客观的卡顿比例**，
不用靠感觉。
